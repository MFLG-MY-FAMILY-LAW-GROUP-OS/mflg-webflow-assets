# Webstudio / Codex Architecture

## Operating Model

Model B is authoritative for this release: the repository owns the complete rendered public application. Webstudio is treated as an upstream visual and content source only.

The reason is practical: the public workflows, catalogs, qualification state, result language, and PDF viewer are rendered by `js/mflg-public-site.js`, not by reusable Webstudio collection markup in the exported HTML.

## Source Boundaries

- Webstudio-origin structure: shared static page chrome in `index.html` and section route shells such as `practice-areas/index.html`, `guides/index.html`, `forms/index.html`, and informational pages.
- Exported/generated files: static route HTML, static images, CSS, JavaScript, and Cloudflare Worker entry `_worker.js`.
- Codex-rendered UI: hero body, homepage sections, Practice Area catalog, DIY Guide catalog, Forms & Calculators workspace, form-router states, calculator panels, and official PDF viewer.
- Catalog data: 50 Practice Areas come from `serviceItems` in `js/mflg-public-site.js`; 50 DIY Guide cards are derived from the same structured service source by `guideFromServiceItem`. Form/result data comes from `data/matter-form-matrix.json`, `data/form-pdf-route-index.json`, and `data/form-pdf-public-actions.json`.
- Codex-owned state and handlers: search, filters, progressive workspace state, canonical public answers, route persistence, same-page reveal/focus/history, form routing, packet/source separation, and PDF viewer events.
- Cloudflare-served files: static HTML/CSS/JS/assets plus `_worker.js` for `/api/official-pdf/...`.

## Webstudio Overwrite Risk

A future Webstudio export could overwrite static HTML route shells and any static visual structure embedded in those files. It would not automatically preserve Codex-owned runtime behavior if exported asset references or root containers changed.

Codex changes are not represented in the Webstudio Builder unless they are manually reflected upstream. Do not maintain the same dynamic workflow markup in both Webstudio and Codex. Keep public workflow markup generated by `mflg-public-site.js` until a deliberate migration moves the dynamic component into Webstudio Collections.

## Release Rule

Webstudio can continue to own brand primitives and static route shells. Codex owns the application layer: data binding, qualification, canonical state, result classification, same-site PDF delivery, tests, and deployment evidence.
